# SURVEY DEMO — АНАЛИТИКА АДМИНИСТРАТИВНОЙ ПАНЕЛИ
## Задача
Реализовать полноценный раздел «Аналитика» в существующей административной панели на основе реальных данных из таблицы public.survey_responses Supabase.
Существующую анкету, авторизацию, RLS-политики и структуру таблицы не изменять.
## Источник данных
Использовать только реальные данные из public.survey_responses.
Не создавать тестовые данные.
Не использовать случайные значения.
Данные доступны только авторизованному пользователю через существующий Supabase Auth.
## Раздел «Аналитика»
Заменить текущий пустой раздел «Аналитика» на рабочий раздел с реальными расчетами.
Показывать данные только после загрузки из Supabase.
Если ответов нет, показывать понятное сообщение: «Недостаточно данных для анализа».
## Основные показатели
Создать блоки:
- Всего респондентов.
- Распределение по полу.
- Распределение по возрастным группам.
- Распределение по частоте состояния напряжения или стресса.
- Распределение по источникам стресса.
- Распределение по способам восстановления.
Для каждого показателя показывать количество ответов и процент от общего числа респондентов.
## Фильтры
Добавить фильтры:
- Пол.
- Возрастная группа.
- Частота состояния напряжения или стресса.
- Источники стресса.
После выбора фильтра все показатели должны автоматически пересчитываться только для выбранной группы.
Добавить кнопку «Сбросить фильтры».
Показывать количество респондентов, подходящих под выбранные фильтры.
## Работа с множественным выбором
Поле stress_sources может содержать несколько вариантов ответа.
Корректно учитывать каждого респондента в каждом выбранном источнике.
Не считать одного человека несколько раз в общем количестве респондентов.
## Визуализация
Использовать понятные простые графики:
- круговые диаграммы или столбчатые диаграммы для распределений;
- карточки с основными числами.
Не использовать сложные графики.
Все графики должны корректно работать при небольшом количестве ответов.
При одном респонденте не создавать ошибочные выводы, а просто показывать фактические данные.
## Открытые ответы
Не менять существующий раздел «Открытые ответы».
Не добавлять искусственный анализ.
Использовать уже созданную логику частотных слов и отображения исходных ответов.
## Адаптивность
Раздел аналитики должен корректно отображаться на компьютере, планшете и смартфоне.
Не создавать горизонтальную прокрутку.
## Безопасность
Не менять RLS.
Не открывать публичный доступ к данным.
Не использовать secret key или service_role.
Не изменять Supabase Auth.
## Не делать на этом этапе
Не реализовывать Excel.
Не создавать новые таблицы.
Не менять структуру survey_responses.
Не изменять публичную анкету.
## Результат
После выполнения раздел «Аналитика» должен отображать реальные данные из Supabase, поддерживать фильтры и пересчет показателей.
Проверить работу на текущем количестве данных.
После выполнения остановиться и не переходить к Excel.
