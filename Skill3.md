# SURVEY DEMO — РЕАЛЬНЫЕ ДАННЫЕ АДМИНКИ
## Задача
Подключить существующую административную панель к реальным данным из таблицы public.survey_responses существующего проекта Supabase. Публичную анкету, ее вопросы, дизайн и механизм отправки ответов не изменять. Существующую авторизацию Supabase Auth не изменять.
## Источник данных
Использовать существующую таблицу public.survey_responses.
Поля таблицы:
- id
- created_at
- gender
- age_group
- stress_frequency
- stress_sources
- difficult_situations
- recovery_methods
Использовать только реальные записи из Supabase. Не создавать фиктивные, демонстрационные или случайные данные.
Данные должны загружаться только после успешной авторизации пользователя в /admin.
## Обзор
В разделе «Обзор» показать реальные данные:
- общее количество респондентов;
- распределение по полу;
- распределение по возрастным группам;
- распределение по частоте состояния напряжения или стресса;
- распределение источников стресса.
Для каждого варианта показывать количество ответов и процент от общего числа соответствующих респондентов.
Поле stress_sources содержит множественный выбор, поэтому один респондент может учитываться в нескольких источниках стресса.
Не придумывать данные и не делать причинно-следственных выводов.
Если данных нет, показать понятное сообщение об отсутствии ответов.
## Открытые ответы
В разделе «Открытые ответы» создать две отдельные карточки.
Первая карточка:
«В каких ситуациях вам особенно трудно справляться со стрессом?»
Использовать данные поля difficult_situations.
Вторая карточка:
«Что помогает вам восстанавливаться после стрессовой ситуации?»
Использовать данные поля recovery_methods.
В каждой карточке сначала показать блок «Часто встречающиеся слова».
Для анализа объединить все ответы на соответствующий вопрос, привести текст к нижнему регистру, убрать знаки препинания и исключить распространенные русские служебные слова, местоимения, союзы, предлоги и другие малоинформативные слова, например: и, в, во, на, с, со, к, ко, у, о, об, от, до, за, из, для, по, при, а, но, или, что, как, когда, если, это, этот, эта, эти, я, мы, вы, он, она, они, мне, меня, мой, моя, мои, свой, свои, не, да, же, бы.
Показывать содержательные слова и реальное количество их упоминаний.
Не скрывать слова только потому, что они встретились один раз.
Сортировать слова по убыванию количества упоминаний.
При одинаковом количестве использовать стабильную сортировку.
Не объединять слова искусственно по смыслу и не придумывать категории.
Если после удаления служебных слов содержательных слов нет, показать понятное сообщение.
Ниже блока с частотными словами в этой же карточке показать все полные исходные ответы респондентов на данный вопрос.
Каждый ответ подписывать «Респондент №N».
Не сокращать и не перефразировать ответы.
## Респонденты
В разделе «Респонденты» показать список всех реальных записей.
Пользователь интерфейса должен видеть названия «Респондент №1», «Респондент №2», «Респондент №3» и так далее, а не технический id как основное название.
Нумерация должна быть стабильной и определяться порядком записей, например по id по возрастанию.
При выборе конкретного респондента показать его анкету полностью:
- Пол
- Возраст
- Частота состояния напряжения или стресса
- Источники стресса
- В каких ситуациях особенно трудно справляться со стрессом
- Что помогает восстанавливаться после стрессовой ситуации
Все ответы показывать полностью.
Для stress_sources корректно отображать все выбранные варианты, включая собственный вариант «Другое», если он был введен.
## Обновление данных
При открытии административной панели загружать актуальные данные из Supabase.
После обновления страницы данные должны загружаться заново.
Предусмотреть понятное состояние загрузки.
При ошибке загрузки показать понятное сообщение об ошибке, не показывать фиктивные данные.
## Безопасность
Получать survey_responses только после успешной авторизации через существующий Supabase Auth.
Не использовать secret key, service_role или пароль базы данных.
Использовать существующие API URL и Publishable key.
Не обходить существующие RLS-политики.
Не добавлять публичный доступ SELECT для anon.
## Не делать на этом этапе
Не реализовывать выгрузку Excel.
Не реализовывать сложные перекрестные сравнения и фильтры раздела «Аналитика».
Кнопку «Выгрузить ответы в Excel» пока оставить неактивной.
Раздел «Аналитика» пока оставить в существующем состоянии.
## Дизайн
Сохранить существующий дизайн административной панели и цветовую гамму.
Не изменять дизайн публичной анкеты.
Не создавать чрезмерные пустые пространства.
Информация должна быть хорошо читаемой на компьютере и мобильном устройстве.
## Важно
Не изменять SKILL.md, SKILL2.md и SKILL3.md.
Не изменять структуру таблицы survey_responses.
Не создавать новые таблицы.
Не создавать тестовые данные.
Не изменять существующую авторизацию.
Не изменять публичную анкету.
## Результат
После выполнения разделы «Обзор», «Открытые ответы» и «Респонденты» должны работать на реальных данных Supabase. Проверить загрузку данных, отображение множественных ответов, частотный анализ открытых ответов и просмотр полной анкеты конкретного респондента. После проверки остановиться и не переходить к аналитике или Excel.
